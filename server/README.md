# DeskPilot Server

Runs on the computer you want to control. The DeskPilot Android app finds it automatically on the same Wi-Fi.

## Run from source

```bash
cd server
pip install .
deskpilot-server --password "choose-a-password"
```

It prints the IP and port to enter in the app (default port **9512/TCP**, discovery on **9511/UDP**).
Allow both through the firewall when prompted (Windows Defender Firewall asks on first run).

Options: `--name "Living room PC"`, `--port 9512`, `--bluetooth` (experimental RFCOMM, Linux/Windows),
`--dry-run` (logs input instead of moving the mouse – useful for testing).

Settings live in `~/.deskpilot/config.json` (password, File Manager root folder, allow/deny commands, Launcher apps).

## Per-OS notes

- **macOS** – grant *Accessibility* permission to Terminal / the packaged app (System Settings → Privacy & Security → Accessibility), otherwise keyboard and mouse events are ignored. Screen mirroring needs *Screen Recording* permission.
- **Linux** – works on X11. On Wayland, pynput can't inject input; log in with an X11 session. Volume uses `pactl`/`amixer`.
- **Windows** – run once as a normal user (not admin). `pycaw` gives exact volume levels.

## Installers for users (Windows / macOS / Linux / Raspberry Pi)

Users never need Python. Each OS gets a normal installer:

| OS | File | What it does |
|---|---|---|
| Windows 10/11 | `DeskPilotServer-Setup-Windows-x64.exe` (+ portable zip) | Start menu, firewall rule, optional start at login, uninstaller |
| macOS (Apple chip / Intel) | `DeskPilotServer-macOS-AppleSilicon.dmg` / `-Intel.dmg` | Drag-to-Applications, menu-bar app |
| Ubuntu / Debian / Mint | `deskpilot-server-linux-x64.deb` (+ tar.gz) | App menu entry, `deskpilot-server` command |
| Raspberry Pi OS 64-bit | `deskpilot-server-linux-arm64.deb` (+ tar.gz) | Same, plus a headless systemd service |

**Build all of them automatically:** push this repo to GitHub, then push a tag (`git tag server-v1.0.0 && git push --tags`).
`.github/workflows/server-release.yml` builds every OS on GitHub's machines and attaches the files to a Release.
`website/download.html` links to `releases/latest/download/<file>`, so the page always serves the newest build.

**Build one locally** (on the OS you are targeting):
```bash
pip install -r packaging/requirements-build.txt
python packaging/build.py          # results in dist/release/
```
Windows also needs Inno Setup 6 (`choco install innosetup`).

**What users see:** the app runs in the tray / menu bar, and opening it shows a settings page at http://127.0.0.1:9513
(phone address, password, start at login, connected phones, quit). It accepts only local connections, and every settings change needs a per-run token.
`--headless` runs without tray or browser (Raspberry Pi, SSH, systemd).

**Code signing (recommended before public launch):** unsigned builds work, but Windows SmartScreen and macOS Gatekeeper show a warning the first time.
Signing a Windows build needs a code-signing certificate. For macOS, add an Apple Developer ID as the `MACOS_SIGN_IDENTITY`, `APPLE_ID`, `APPLE_TEAM_ID`,
`APPLE_APP_PASSWORD` repository secrets, and the workflow signs and notarizes the DMG automatically.

## Add or edit remotes

Remotes are JSON files. Bundled ones are generated by `tools/gen_remotes.py`; drop your own into
`~/.deskpilot/remotes/` and tap *Reload remotes* (or restart). Format is documented at the top of `deskpilot_server/remotes.py`.

## Security

Every message after the handshake is AES-256-GCM encrypted with a key derived from the password (PBKDF2-SHA256, 100k rounds, per-run salt).
Without a password the channel is still encrypted but anyone on your network with the app can connect – set one.
The Command / Custom Run / Scripts remotes execute shell commands: disable with `"allow_commands": false` if you don't need them.
